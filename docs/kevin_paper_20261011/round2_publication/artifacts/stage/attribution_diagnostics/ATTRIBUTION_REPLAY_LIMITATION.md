# Attribution probability replay limitation

The recovered attribution output retains `blocked_cloud_probability_replay_review`. The original maximum absolute probability tolerance, 0.0001, has not changed. Two of the 100 historical reader cases exceeded it: image_005 (0.00011771917343139648) and image_010 (0.00037366151809692383). Both retained the same predicted class. The largest observed difference is 0.03737 percentage points of probability. This is a numerical probability-replay discrepancy, not an observed class disagreement.

All 115 saved native maps were valid under the fixed map checks. The original run reached its per-case logit/mode/gradient checks, the final parameter-restoration assertion and the plot writes before a separate NumPy-integer JSON serialization error. The postprocessing recovery independently checked saved probabilities, map mass, historical-map identity, randomization data and payload readback. It did not recreate an in-memory model or rerun those original runtime assertions. Both the failed original directory and the recovered blocked directory remain preserved.

Static inspection identified a relevant execution difference: the numerical evaluator processes batches of up to 64 with the shared stage-forward function, whereas attribution processes one image at a time with the model's forward method. Batch-dependent floating-point arithmetic is a plausible explanation; it has not been established as the cause here. PyTorch documents that mathematically equivalent batched and single-example computations need not produce identical floating-point results. [PyTorch numerical-accuracy notes](https://docs.pytorch.org/docs/stable/notes/numerical_accuracy.html).

No checkpoint, threshold, prediction, class target, tolerance or map is changed to make the check pass. The existing maps may be displayed only as **diagnostic attribution results with a failed replay check**, prominently marked in the gallery, figures and atlas. They explain the recorded single-image forward predictions; they are not claimed to reproduce every frozen evaluation probability within the original tolerance. Same-class agreement and a small absolute discrepancy do not erase the failed prespecified check.

The completed quantitative evaluation remains separate and its original predictions are unchanged. The diagnostic appendix retains the original blocked marker and hashes alongside visibly labeled derivatives; its own completion marker means only that the appendix was assembled and verified. Native arrays and quantitative map tables remain unchanged. Neither maps nor image perturbations establish anatomical localization or clinical readiness.

A later numerical diagnostic, if needed, requires its own recorded protocol and new output. It should first compare identical preprocessed tensors, fixed checkpoint state, explicit float32/TF32 settings, exact original batch membership/order, inference versus gradient-enabled forward passes and batch-size effects, without fitting or choosing models. The original blocked result must remain. No such diagnostic or further inference has been performed for this note, and none is necessary to retain the failed check honestly in this report.
