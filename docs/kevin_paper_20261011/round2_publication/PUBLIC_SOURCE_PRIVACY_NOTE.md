# Public source scope and privacy review

`PUBLIC_SOURCE_ALLOWLIST.txt` contains exact repository-relative paths for the Round 2 scientific source, frozen protocols, synthetic tests, design documentation and aggregate source-acquisition/preprocessing evidence. It has no directory entries or wildcards. At this update, the exact list contains 75 paths; 0 were already tracked. The review did not stage, commit, push, edit frozen source, run model inference or change cloud resources.

The research-weight export source, its synthetic guards and the aggregate completed export-verification record are included, but no exported weight binaries or performance result tables are authorized by this list. The completed verification record contains model seeds, selected epochs, tensor-count and checksum/parity evidence only; it has no clinical rows or connection details. Synthetic verification records describe invented fixtures and randomly initialized models only. The final-attribution serialization recovery source, tests and independent review are included; they preserve frozen source and explicitly distinguish artifact checks from real model execution. The copied migration integrity helper has ten passing self-contained synthetic tests; its source provenance is separate from any real experiment receipt.

This is a source and aggregate integrity-evidence release list. It is not a performance-result export or a list of every file needed to rerun real-patient inference. Model-result tables, predictions, graphs, checkpoints and completed-run evidence require a separate reviewed export after retrieval and verification. Frozen prospective protocols and reviews retain their original wording. The publication owner must update the current Methods, limitations and Results completion wording from verified execution evidence and preserve negative clinical findings.

The new clinical source and protocols contain aggregate class counts, seed identities, model design and whole-file integrity hashes. They do not contain the actual clinical subject rows. Source code describing how to group patients or read private manifests does not authorize publishing those manifests. Synthetic fixtures contain invented case identities and probabilities rather than clinical records.

The Harvard acquisition, preprocessing and QC summaries contain aggregate counts, source citations, archive/manifests hashes and whole-montage hashes. The montage images and individual clinical records are excluded. Harvard's public release contains 29 T1 volumes, of which 19 are eligible for the separately defined AD/control endpoint; an open source license does not remove the need to review image/header privacy before redistribution. AlzaSet's acquisition summary and quarantine rationale are included; its image inventory, filename tokens, similarity pairs and images are excluded. It has not been used for model training or prediction.

The following stay outside this allowlist:

- All clinical individual manifests, subject mappings, labels paired with patient identifiers, per-patient predictions, raw headers, scan inventories, QC panels and raw/prepared MRI. This includes `round2_clinical/prepared/patients.json` and clinical evaluation manifests. The development manifest is currently untracked **and not ignored**, so do not use blanket staging.
- All pretrained/trained weights and checkpoint payloads. The official ImageNet `.pth` copy is also untracked **and not ignored**. Its hash and acquisition source can be reported without committing the binary.
- All archives, transfer manifests, payload manifests, caches, logs, synthetic generated outputs, prepared stage masks and row-level preparation tables.
- Cloud operations, Pod/volume inventories and identifiers, SSH hosts/ports/keys/fingerprints, billing state, handoffs, private transfer/install paths and their real execution records. The operational review/catalog documents are omitted. A narrow exception is the byte-preserving generic completed-suite migration helper and synthetic tests copied under `reconstruction/`, with portable usage and source hashes; no real migration receipt, payload manifest or archive accompanies those public copies. Scientific smoke-test source is included because it checks model/gradient/BatchNorm behavior and contains no resource identity or credentials.
- Private correspondence, recordings/transcripts, email references and raw official metadata snapshots containing scan-level file lists. Source documentation can cite the official provider without republishing the full snapshot.

The retained frozen training READMEs contain scientific design and generic directory examples without connection details. Portable documentation copies under `usage/` replace only the personal absolute interpreter path with `python`; the frozen originals are unchanged and excluded from this public list. Two access-audit originals referring to private email provenance are omitted; the public Methods and data/limitations document contain the source citations and aggregate rationale. A path to a private input is a dependency reference, not permission to publish that input.

Already tracked dependencies are deliberately not repeated in the staging allowlist. They include `training/train_candidate.py`, `training/evaluate_candidates.py`, `posthoc_robustness/stress_test.py`, `analysis/summarize_frozen_evaluation.py`, `analysis/plot_evaluation_figures.py`, `analysis/analysis_protocol.json`, the unchanged `preprocess_clinical_t1.py`, and `src/grad_cam.py` / `src/explainability_validation.py`. Their existing tracking was checked. The new `round2_corner_audit/corner_audit.py` runtime dependency is explicitly included. The transitively imported `src/research_validation.py` is already tracked as well. The existing tracked `requirements.txt` and `training/requirements-analysis.txt` cover the scientific packages, including PyTorch/torchvision, Pillow, NumPy, SciPy, scikit-learn, matplotlib, pandas, nibabel and pypdf. The separately tracked `requirements-verification.txt` is for its own lightweight verification environment; its different pinned versions must not be silently treated as the training lockfile.

The additional unrestricted T1 search note and JSON contain only aggregate eligibility decisions and primary-provider links; they found no newly verified qualifying AD/control cohort and authorize no dataset acquisition. They include no patient rows, private correspondence or connection details.

Reproduction still requires lawful acquisition of the cited source data, the private prepared manifests and their pinned inputs, existing baseline/checkpoint identities, and the separately verified result inputs. The Harvard raw provider metadata used by acquisition verification must be obtained from the provider locally; it is intentionally not included here. No claim of a self-contained patient-data release is made.

Before committing, recheck every exact listed file, the final staged diff and any newly added result list. Do not recursively stage a Round 2 directory. Source names alone are not a permanent privacy guarantee: a later edit that adds records, credentials or resource details requires another review. The present review only creates this allowlist and note and leaves all excluded files unchanged.
