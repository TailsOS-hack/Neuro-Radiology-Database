# Execution contract and remaining gates

This package implements research mechanics and admission checks. It is not a completed clinical validation study. The current source inventory has zero acquired eligible patients. Do not rent a GPU to discover that the data gate is still blocked.

1. Obtain provider approval and the actual released dictionaries/images. Map provider fields into the normalized scan and assessment records, preserving original field/value evidence in private storage. A diagnosis cannot come from a repository name, cognitive score alone, or biomarker positivity. Confirm provider permission for the chosen compute/storage arrangement and any future derivative/checkpoint release.
2. Normalize global person identities and institutions across sources before partitioning. The primary scan is the earliest eligible scan; all other visits and derivatives remain with that person. Bind the source scan/assessment files and replay the 180-day matching rule. Preserve the 90-day analysis and repeated scans separately.
3. Record the actual development and untouched external institutions and class counts. The sample-size simulator takes explicit paired correctness assumptions; its output is not a minimum-N calculator. Review and justify those assumptions, run the frozen 10,000-bootstrap design simulation, and review the resulting power/precision before authorizing training. If adequate data are unavailable, the superiority study remains unresolved.
4. Supply a reviewed preprocessing configuration with hashes of N4, SynthStrip, ANTs, their runtime, weights, template and mask. Pin that configuration reference and its version hash in the execution protocol. Run `prepare` before `freeze-development`. Diagnosis/prediction-blinded anatomical review must record actual passes or failures; pending review templates are not approval. Bind review file hashes only after that review. Retain eligible external processing failures for evaluation.
5. Prepare the unchanged old comparator's historical nine-slice inputs separately, pinned to the same source T1. It must use the existing binary auxiliary heads, preprocessing and probability aggregation. New preprocessing cannot silently replace the comparator's original pipeline. The old adapter requires the exact prior checkpoint and preprocessing hashes.
6. After a development authorization is created, stage its exact source and artifact bytes at the paths referenced by that authorization. A relocated or changed file invalidates the freeze. Verify the environment and B300 live price before provisioning: GPU rate no higher than $8.99/hour, machine ceiling $10/hour. Run the bounded search and the three selected final seeds there. The trainer requires B300 CUDA; synthetic tests use small CPU fixtures. A stopped/failed run is not complete and cannot be selected silently.
7. Retrieve and verify all checkpoints, histories and run receipts before deleting compute and storage. Perform candidate selection replay, calibration, statistics and figures on the local Mac. Its tested package versions are recorded in `research/dementia_round3/requirements-local-tested.txt`; that file is not a frozen B300/preprocessing environment or proof of independent reproduction.
8. Use `predict-paired --partition calibration` with the raw uncalibrated bundles, then `calibrate --model both`. The calibration artifact binds the complete reserved patient roster and raw checkpoint identities. Final new/old/recalibrated-old bundles, completed final-run index, selection receipt, preprocessing and thresholds must all be verified before `freeze-external`. Opening that freeze closes development for this protocol.
9. Use `predict-paired --partition external`, `evaluate` and `report` with the same external authorization. Every eligible patient, including abstentions and failures, must appear once. The report reproduces primary statistics and raw final-seed loss/site/calibration figures. It does not certify secondary analyses that have not run.

Keep patient records, predictions, scans, model run artifacts, application identities and agreement records under the ignored `round3_private` directory or an equivalently protected local destination. Public outputs require provider-term and disclosure review. No command in this package allocates a paid resource, sends a message or submits an application.
