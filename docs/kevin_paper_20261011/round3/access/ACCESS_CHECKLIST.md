# Access checklist and decision points

This checklist records necessary work; unchecked items are not satisfied by the existence of a draft.

## Applicant review

- [x] Confirm a truthful applicant name, salutation, contact address, country/city and current independent student status. Use an institution only if a real relationship permits it.
- [x] Confirm the request is new; avoid duplicate submissions.
- [ ] Identify all actual people who would access participant data. Do not invent a supervisor, principal investigator, institution or research approval.
- [ ] Record an actual ethics approval, exemption or non-human-subjects determination only if documented. Otherwise disclose its absence and resolve any provider requirement before attesting.
- [ ] Inspect exact account/DUA terms personally, including any eligibility or signatory condition. NACC DUA and typed signature were entered after explicit action-time confirmation. The separate accuracy certification was explicitly confirmed and the application submitted with provider acknowledgment. No account creation, CAPTCHA completion or patient-data acquisition by the agent is recorded.

## NACC / SCAN

- [ ] Review the separate private local NACC application draft. It is excluded from publication; the public scientific description is [available here](PROJECT_DESCRIPTION.md).
- [x] Supply the first-page required values. The actual available institution type `Other` can support a truthful independent description; approval remains NACC's decision.
- [ ] Review the form's disclosure that investigator name, institution, title and aims enter the public project list.
- [x] Inspect NACC DUA and generated response confirmation after authorized identity entry.
- [x] Complete the explicitly confirmed accuracy/electronic-signature certification; inspect dataset/project fields and verify final submission receipt.
- [ ] Verify actual delivery, separate standardized-image access instructions and provider-permitted use before downloading or processing patient data.
- [ ] Check existing projects/publications for significant overlap and refine the hypothesis where needed. This draft does not certify novelty.
- [ ] Request released T1 **images**, UDS diagnosis and visit dates, scan linkage, source/site and QC information. Confirm permitted external compute and derived-model sharing in the actual agreement.

## BrainLat

- [ ] User creates or identifies an eligible Synapse account through the official site and handles its terms.
- [ ] Review the five required fields: form email, researcher name, institution, researcher email and Synapse username. An independent description can be proposed truthfully; provider acceptance is unknown.
- [ ] User reviews and submits the [MRI access form](https://docs.google.com/forms/d/e/1FAIpQLSfSH-vHFvfIg4G0xCQlpfOGRHU4AutftzTQLLTp9GYtMk99aA/viewform). No project-description field was observed.
- [ ] On approval, confirm current MRI participant-code mapping, T1 availability, site/diagnosis linkage, permitted use and the release-specific license. EEG availability alone does not supply the requested MRI cohort.

## MIRIAD

- [ ] Recheck the [official XNAT endpoint](https://miriad.drc.ion.ucl.ac.uk/atrophychallenge); the current timeout prevents registration-field verification.
- [ ] Inspect the actual registration fields and terms when reachable. Do not infer an email restriction or invent the unseen fields.
- [ ] User registers/accepts terms if eligible. Preserve UCL's acknowledgement/citation requirements and no-redistribution restriction.
- [ ] Verify subject labels and repeated scans after authorized acquisition; reserve its role before observing model outcomes.

## Before modeling any newly approved data

- [ ] Pin release/version, terms, file checksums and a private provenance record.
- [ ] Verify three-dimensional T1 files, patient/visit/scan identities, diagnosis definition and timing, source/site and acquisition/QC fields. Report absent variables and failed scans.
- [ ] Audit overlap across repeated scans, dataset versions and source families, including NACC/SCAN and any other shared recruiting centers.
- [ ] Freeze patient/source-aware development partitions and an untouched external evaluation role before model selection.
- [ ] Keep subject-level images, tables, credentials and operational access evidence private; publish only permitted aggregate results and code.

No checklist item guarantees institutional acceptance, a particular number of eligible patients, superior model performance or clinical readiness.
