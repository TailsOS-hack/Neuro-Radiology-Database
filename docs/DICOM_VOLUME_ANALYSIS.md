# DICOM input and volume-level dementia analysis

Added 2026-11-14. This document covers what the DICOM path does, how it was
checked, what it showed about the existing dementia models on real scans, and
what it does **not** establish. The aggregate evidence is in
[`dicom_volume_verification.json`](dicom_volume_verification.json) and is
regenerated by [`scripts/verify_dicom_volume_pipeline.py`](../scripts/verify_dicom_volume_pipeline.py).

**No model was retrained and no checkpoint was replaced.** The production
`models/alzheimers_classifier.pt` and all research checkpoints are byte-for-byte
unchanged. Nothing here is evidence of clinical performance.

## What was added

| Piece | File | Role |
|---|---|---|
| Volume container | `src/mri_volume.py` | One representation for every scan: voxels in closest-canonical RAS+ order plus the voxel-to-world affine. Identifying header fields are held separately and never written or logged. NIfTI export with the two hashes the Round 3 patient manifest pins. |
| DICOM reader | `src/dicom_io.py` | Files, folders or zip archives; classic single-frame series and Enhanced multi-frame MR; series discovery and T1 ranking; slice ordering and spacing from positions; per-slice rescale; fails loudly on missing slices, irregular spacing, mosaics, colour captures and undecodable pixel data. |
| Volume analysis | `src/volume_analysis.py` | Scan -> the exact slices the clinical AD/CN checkpoints were trained on -> ensemble score -> Grad-CAM for every slice of the trained band, stacked into a 3D map that overlays the scan. |
| Interactive viewer | `src/volume_viewer.py`, `src/volume_viewer_template.html` | One self-contained HTML page per analysis: three linked slice views with the stacked Grad-CAM overlay, a rotating 3D projection and per-slice charts. No network access and no identifying header fields. |
| Display helpers | `src/scan_view.py` | Slice rendering and header-derived form values for the GUI. |
| GUI | `src/radiology_report_gui.py` | Open a DICOM file/folder/zip or NIfTI, page through slices, run the single-slice cascade on the displayed slice or the whole-volume analysis, export the 3D map. |
| Verification | `scripts/verify_dicom_volume_pipeline.py`, `tests/test_dicom_io.py`, `tests/test_volume_analysis.py`, `tests/test_volume_viewer.py`, `tests/test_scan_view.py`, `tests/test_gui_scan_flow.py` | See below. |

## Using it

```bash
# List the series in a study, most likely 3D T1 first
python -m src.dicom_io /path/to/study

# Convert one series to canonical NIfTI (+ JSON sidecar without identifying fields)
python -m src.dicom_io /path/to/study --to-nifti scan.nii.gz

# Whole-volume research analysis with the stacked Grad-CAM map
python -m src.volume_analysis /path/to/study --output results/

# Rebuild the interactive viewer from a results folder written earlier
python -m src.volume_viewer results/
```

`results/` then holds:

| File | Content |
|---|---|
| `result.json` | Ensemble and per-member P(AD), preparation geometry, per-slice share of attention, warnings, research notice. No identifying fields. |
| `anatomy.nii.gz`, `gradcam.nii.gz` | The scan and the attention map on the model's 1.5 mm RAS grid (same shape and affine). |
| `gradcam_native.nii.gz` | The same map resampled onto the scan's own voxel grid: one value per original voxel, so it overlays the DICOM series directly in 3D Slicer, ITK-SNAP or FSLeyes. |
| `montage.png`, `projections.png` | Every analysed slice with its heatmap; axial/coronal/sagittal maximum-intensity projections of the map. |
| `viewer.html` | The same scan and map in one page that opens in any current browser, offline: axial, coronal and sagittal views that move together, a 3D projection to rotate, the share of attention and the single-slice score for every slice of the slab. No identifying fields; it does contain the scan, so treat it like the scan. |

In the GUI: **Scan** (file) or **DICOM Folder...** loads a scan, the slider pages
through axial slices, **Series...** picks another series of the study,
**Analyze Volume** runs the whole-scan analysis, **Save 3D Map...** writes the
files above and offers to open `viewer.html` in the browser. The folder stays
on screen ("3D map saved in: ..."), because a browser launcher can report
success without opening anything. Patient name, ID
and date of birth are taken from the header, and are removed again when another
image is opened.

Compressed transfer syntaxes (JPEG, JPEG-LS, JPEG 2000) need the optional
`pylibjpeg` plugins from `requirements.txt`; uncompressed and RLE files do not.

`--checkpoints` runs another ensemble of the same family, for example the fold
models written by `src/train_dementia_volume.py`. Checkpoints are opened in
PyTorch's weights-only mode (tensors and plain metadata only), so a file
received from someone else is refused rather than executed if it carries
pickled code.

## How a scan becomes model input

1. Slices are ordered by `ImagePositionPatient . (row x column)`, never by file
   name or `InstanceNumber`; the slice step comes from those positions, never
   from `SliceThickness`. The affine is built from `ImageOrientationPatient` and
   `PixelSpacing` and converted from DICOM LPS+ to RAS+.
2. `RescaleSlope`/`RescaleIntercept` are applied per slice. Integer scans stay
   exact; real-valued rescales keep double precision.
3. The volume is reoriented (no resampling) to closest-canonical RAS+.
4. `prepare_clinical_volume` reproduces
   [`preprocess_clinical_t1.py`](kevin_paper_20261011/preprocess_clinical_t1.py)
   (recipe `exploratory_t1_axial_v1`) operation for operation: 1.5 mm RAS grid,
   largest foreground component, nine axial slices at 45-85% of the cranial
   extent, per-volume 1st/99th percentile window, square pad, 224 px.
5. Each ensemble member scores the scan as `softmax(mean of the nine slice
   logits)`; the ensemble is the equal-weight mean of member probabilities;
   the label uses the fixed 0.5 threshold on P(AD). This is the frozen Round 2
   aggregation.

## The 3D Grad-CAM map

* Grad-CAM is computed at the last feature block **for every 1.5 mm axial slice
  between the first and last protocol slice** (a contiguous slab of roughly 40-45
  slices), in one backward pass per batch. The prediction itself still uses only
  the nine protocol slices.
* Slice maps are returned raw. They are **not** min-max normalised one by one:
  a slice the model barely used stays dark, and the stack is scaled once by its
  volume-wide maximum. Each member is scaled by its own maximum before the
  members are averaged, so no member dominates through feature scale.
* The gradient-enabled forward pass must reproduce the plain forward logits
  (tolerance 1e-4) or the explanation is refused.
* The native map is 7 x 7 per slice. It is coarse, and in the scans checked here
  it includes regions outside the brain (skull, scalp, image borders). It shows
  what this model responds to in each slice. Only the slices the score is
  computed from (nine, for the Round 2 ensemble) fed the result; on the other
  slices of the slab the map shows what the same model responds to when given
  that slice alone. It is not a localisation of pathology, and a
  better-looking map is not evidence of a better model.
* `viewer.html` draws that same volume-scaled map. The slice views use one blue
  ramp whose opacity follows the value, with a control that hides values below
  a chosen level. The 3D view lays the map, front to back, over a summed
  projection of the scan: it is a picture for orientation, not a measurement,
  and the slice views and `gradcam.nii.gz` are the reference.
* The page says which slices the score is computed from and which ones have a
  map, and words its claims accordingly; a slice without a map reads "no map",
  never "attention 0.00". The scan and the map are embedded as compressed bytes
  with a CRC-32, which also catches voxels that arrive in another order. A page
  that cannot unpack them exactly says so, draws nothing and offers no
  controls.
* The research notice carries its sentence about the attention map only on a
  result that has a map. A page rebuilt with `python -m src.volume_viewer`
  shows the notice and warnings recorded in `result.json` when the scan was
  analysed; rebuilding does not bring them up to date.
* The 3D view assumes a head-sized volume. It lowers its exposure for a volume
  whose rays are much longer in the current view, but it samples without
  interpolation, so a series only a few voxels thick shows banding there. The
  slice views are not affected.
* `python -m src.volume_viewer` reads `anatomy.nii.gz` and `gradcam.nii.gz`
  through the same canonical reader as every other scan and compares their
  geometry with `result.json`. A file that another tool re-saved in a different
  voxel order is put back; one that no longer sits on the recorded grid is
  refused.

## Verification (2026-11-14)

All numbers below are in `dicom_volume_verification.json`.

**Geometry.** 96 synthetic series (48 voxel orders x an axis-aligned and an
oblique affine, shuffled file names, some with reversed instance numbers), one
Enhanced multi-frame object and one per-slice-rescaled series: 98/98 read back to
the source volume (largest affine deviation 5e-8 mm) and 98/98 agree with
`dcm2niix`, an independent implementation (largest affine deviation 3.4e-4 mm,
its single-precision header). The canonical reorientation matches
`nibabel.as_closest_canonical`.

**Real pixel decoding.** The real scanner files shipped inside pydicom decode to
identical pixels in explicit and implicit VR, big endian, RLE, JPEG 2000 lossless
and JPEG-LS lossless.

**Input parity with the frozen pipeline.** On the 20 T1 volumes of OpenNeuro
ds007561 v1.0.0 (public, CC0; a previously evaluated, historical cohort):

* published NIfTI -> in-memory path: slices pixel-identical to the frozen script's
  PNGs for 20/20 scans, with identical slice indices, crop and intensity window;
* integer voxels written as a sagittal DICOM series with shuffled file names ->
  DICOM reader: volume identical to the NIfTI for 20/20, slices pixel-identical
  to the frozen script for 20/20.

The frozen script's SHA-256 (`bc3e1c70...`) equals the `PREPROCESSOR_SHA` pinned
by the Round 2 clinical trainer.

**Published results reproduced.** Run through the new path, the three Round 2
clinical checkpoints give 14/15, 10/15 and 15/15 correct on the 15 binary cases
and the ensemble gives 14/15 with every case labelled CN, exactly the counts in
[RESULTS.md](kevin_paper_20261011/round2_publication/RESULTS.md).

**Tests.** 135 new tests in seven files: 107 for the DICOM reader, the volume
analysis, the interactive viewer, the display helpers and the GUI scan flow,
and 28 for the trainer and the OASIS-1 loader described in
[OASIS1_VOLUME_TRAINING.md](OASIS1_VOLUME_TRAINING.md). The suite is 295 tests
in total with a display; the GUI-flow tests need `xvfb-run` on a headless
machine and are skipped otherwise. `pydicom` was added to
`requirements-verification.txt` so the 33 DICOM contracts, the 8 display-helper
tests and the 13 viewer tests that need no other package run in the offline CI
job; that job's set of pre-existing import errors is unchanged. Fourteen
further viewer tests load pages in headless Chromium and read back what is on
screen: the unpacked volumes match their checksums; a marker voxel is bright
where each view's drawn edge letters say and dark at the mirror image of that
place, and a lone voxel of attention is tinted at its own place only; the 3D
picture has the patient's right on the side its letter R points to; the
positions, slice numbers and scores are the ones in the summary; touch, layout
and the controls behave; text from the analysis stays text; a page without a
map works; and a damaged page draws nothing. They run only where Node.js with
Playwright and its Chromium are installed.

`python scripts/check_viewer_tests.py` checks that these tests can fail. It
applies each of 49 deliberate defects (a mirrored view or map, swapped edge
letters, a reversed chart, a dropped crop offset, a checksum that is not
checked, and so on) to a temporary copy of the viewer and runs the 31 viewer
tests on it; every defect makes that run fail.

## What this showed about the existing dementia models

**1. The four-class stage model must not be read on raw scans.** Its training
images are skull-stripped, atlas-aligned axial slices. Given the nine with-skull
slices of each of the 20 research scans, it labelled **180 of 180 slices
MildDemented or VeryMildDemented and 0 NonDemented, including every slice of
all 14 cognitively normal participants.** This is not a statement about its
accuracy on images like its training data; it is a statement that a DICOM series
straight from a scanner is a different kind of image. The GUI therefore attaches
a caution to the label, the heatmap caption and the report whenever the stage
model is applied to a slice of a loaded scan. Whether skull stripping brings
raw scans back into its domain was **not** established: no validated
brain-extraction tool was available in the environment where this was built, and
an improvised morphological mask failed visibly on most scans, so that probe was
discarded rather than reported.

**2. The clinical AD/CN ensemble runs on raw scans but remains weak.** It is the
only dementia model here trained on real with-skull volumes, so it is the one the
volume path uses. Its documented record is unchanged: 43 development patients
from one source; all 19 fresh Harvard participants labelled AD (specificity
0/10); all 15 OpenNeuro participants labelled CN. Every output carries that
notice.

**3. The single-slice router sends raw slices to the tumour branch.** It was
trained to tell the tumour dataset from the dementia dataset, and a with-skull
slice looks like the former. In the single-slice cascade a raw DICOM slice will
therefore normally not reach the dementia specialist at all.

## What "better" requires

The stage model is at ceiling on its own benchmark (99.9% on a split whose
patient independence cannot be established), so there is nothing to gain there,
and no amount of training on those 2D images teaches a model to read raw scans.
A dementia model that performs on DICOM volumes needs **labelled 3D volumes with
patient identities**: more of them, and from more than one site.

Two published results set expectations for what such a model can honestly
report. A reproducible evaluation that split by patient and kept test sets
untouched ([Wen et al., *Medical Image Analysis* 2020](https://arxiv.org/abs/1904.07773))
found that more than half of the CNN papers it surveyed may have suffered from
data leakage, that the 3D approaches it compared performed similarly to each
other, and that none beat an SVM on voxel-based features. A study of 2D CNNs
([Yagis et al., *Scientific Reports* 2021](https://www.ncbi.nlm.nih.gov/pmc/articles/PMC8604922/))
measured slice-level splitting inflating test accuracy by about 30 percentage
points on OASIS, and reaching about 96% on *randomly labelled* data where a
patient-level split gave 50%. Accuracies near 100% on slice datasets, including
this project's own stage benchmark, should be read in that light.

The preparation, scoring and 3D attribution code is independent of which
checkpoint it is given, so a model trained on such data plugs into the same
path. A patient-level, cross-validated trainer for exactly that is prepared in
`src/train_dementia_volume.py`, with OASIS-1 as its first intended cohort; it
has not been run on OASIS-1 yet. See [OASIS1_VOLUME_TRAINING.md](OASIS1_VOLUME_TRAINING.md). Cohort conversion for the gated Round 3 workflow is covered by
`python -m src.dicom_io <study> --to-nifti <out>`, whose record carries the
`volume_sha256` and `canonical_volume_sha256` the patient manifest requires; the
hash is computed the same way `research/dementia_round3/data.py` recomputes it
(covered by a test). The Round 3 package itself was not modified.

## Limits

* Software verification only. The scans used are a small, previously observed
  public cohort with a single AD participant; no performance claim follows.
* Contrast detection from header text and timing is a heuristic warning, not a
  guarantee that a series is a T1 volume.
* Siemens mosaics, colour secondary captures, non-spatial multi-frame objects
  and series with missing slices are refused, by design.
* Philips private scaling is not applied (standard rescale only). Intensities are
  windowed per volume before the model sees them, so a uniform scale factor does
  not change the input.
* Gantry-tilted (sheared) stacks keep an exact affine and are flagged; they are
  resampled to an orthogonal grid during preparation.
